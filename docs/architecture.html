Factory Inventory Management System

Architecture overview: a Vue 3 single-page app talks to a FastAPI backend over JSON, which serves in-memory data loaded from JSON files. There is no database.

Data Flow

  1. User changes a filter.
    The filter bar updates shared refs in useFilters.js. Period is mapped to a month value, and the rest are sent as-is.
  2. View reloads its data.
    The view calls a method in api.js. Only non-all filter values are added to the query string.
  3. FastAPI receives the request.
    Query parameters are parsed into optional arguments on the route handler in server/main.py.
  4. In-memory filtering.
    apply_filters applies warehouse, category, and status. filter_by_month handles month or quarter by substring match on order_date.
  5. Response is validated.
    Pydantic models shape the JSON output for inventory, orders, demand, and backlog. Dashboard and reports return plain dicts or lists.
  6. Computed properties render the UI.
    Raw API data sits in ref() values. Charts, totals, and tables are derived through computed().

Known Gaps

Issues found while mapping the code. Verified against the running backend on port 8001.

StatusAreaFinding
Broken Tasks api.js calls /api/tasks (GET, POST, PATCH, DELETE). The backend has no such routes and returns 404. App.vue calls loadTasks on mount, so a 404 is logged to the console on every page load. The failure is caught, so the UI still works with the mock tasks.
Broken Purchase orders api.js defines createPurchaseOrder and getPurchaseOrderByBacklogItem against /api/purchase-orders. The backend has no such routes (404), and no view calls these methods.
Inconsistent Reports Reports.vue calls axios directly with a hardcoded URL instead of going through api.js.
Inconsistent Backlog view Backlog.vue exists but has no route in main.js. Backlog data is shown through BacklogDetailModal on the Dashboard.
Limitation Dashboard filters /api/dashboard/summary applies the status filter to orders only. Inventory and backlog totals ignore it.
Setup Security CORS allows all origins with credentials enabled. The API base URL is hardcoded to localhost:8001. Auth is mock data only. This is acceptable for a local demo, not for deployment.

Running Locally

  • Both servers: ./scripts/start.sh (stop with ./scripts/stop.sh)
  • Backend: cd server && uv run python main.py, then open http://localhost:8001/docs for the interactive API docs
  • Frontend: cd client && npm install && npm run dev, then open http://localhost:3000
  • Tests: pytest against tests/backend
